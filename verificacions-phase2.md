# Phase 2 Engineering Standards / Estandares de ingenieria - Fase 2

These standards are approved project guidance for human contributors and coding agents. Both language columns are normative and must be kept equivalent when updated.

Estos estandares son la guia aprobada del proyecto para colaboradores humanos y agentes de codigo. Ambas columnas son normativas y deben mantenerse equivalentes al actualizarlas.

| Category / Categoria | Approved standard (English) | Estandar aprobado (Espanol) | Repository fact / Hecho del repositorio |
|---|---|---|---|
| Language / Idioma | Write source code identifiers, comments, docstrings, and technical messages in English. User-facing UI copy follows the product's chosen locale. | Escribe en ingles los identificadores, comentarios, docstrings y mensajes tecnicos del codigo. Los textos de interfaz siguen el idioma elegido para el producto. | API literals and model fields are English in [routes.py](backend/app/routes.py); dashboard labels are English in [kpi-row.tsx](frontend/src/components/dashboard/kpi-row.tsx). |
| Documentation / Documentacion | Provide project documentation in English and Spanish. Keep the paired documents structurally and factually equivalent in the same change. | Publica la documentacion del proyecto en ingles y espanol. Mantiene los documentos equivalentes en estructura y contenido dentro del mismo cambio. | [README.md](README.md) links to [README.es.md](README.es.md), and vice versa. |
| Naming / Nombres | Follow language conventions: React components and types use PascalCase; component filenames use kebab-case; TypeScript variables and functions use camelCase; Python functions and variables use snake_case. | Sigue las convenciones del lenguaje: componentes React y tipos en PascalCase; archivos de componentes en kebab-case; variables y funciones TypeScript en camelCase; funciones y variables Python en snake_case. | Examples: [kpi-card.tsx](frontend/src/components/dashboard/kpi-card.tsx), `KPICard` in that file, and `generate_mock_movements` in [routes.py](backend/app/routes.py). |
| Frontend architecture / Arquitectura frontend | Keep screen composition, reusable components, domain calculations, and domain types in their respective modules. Avoid embedding substantial business calculations in presentation components. | Separa composicion de pantalla, componentes reutilizables, calculos de dominio y tipos en sus modulos correspondientes. Evita incluir calculos de negocio sustanciales en componentes de presentacion. | [App.tsx](frontend/src/App.tsx) composes the screen; [financial-utils.ts](frontend/src/lib/financial-utils.ts) calculates KPIs and monthly data; [financial-types.ts](frontend/src/lib/financial-types.ts) defines domain types. |
| Frontend structure / Estructura frontend | Group feature-specific components by feature; place broadly reusable UI primitives in the shared UI area. Keep the structure proportional to the feature size. | Agrupa los componentes especificos por funcionalidad y coloca las primitivas UI reutilizables en el area compartida. Mantiene la estructura proporcional al tamano de la funcionalidad. | Dashboard components are under [components/dashboard](frontend/src/components/dashboard/kpi-row.tsx); shared Card and Skeleton components are under [components/ui](frontend/src/components/ui/card.tsx). |
| Backend architecture / Arquitectura backend | Keep API boundaries, request/response models, and input validation explicit. Split routers or domain services when growth makes the current module difficult to maintain; do not add layers without a concrete need. | Mantiene explicitos los limites de API, los modelos de entrada/salida y la validacion. Separa routers o servicios de dominio cuando el crecimiento dificulte mantener el modulo actual; no agrega capas sin una necesidad concreta. | [routes.py](backend/app/routes.py) currently contains typed models, helpers, and routes in one module; [main.py](backend/app/main.py) registers the router. |
| API contracts / Contratos API | Type API parameters and responses, validate them at the API boundary, and declare response models for endpoints. Keep frontend domain types aligned with the API contract. | Tipa los parametros y respuestas de API, validalos en el limite de la API y declara modelos de respuesta para los endpoints. Mantiene alineados los tipos de dominio frontend con el contrato API. | [routes.py](backend/app/routes.py) uses Pydantic models, `Literal` query types, and FastAPI `response_model` declarations; corresponding TypeScript shapes are in [financial-types.ts](frontend/src/lib/financial-types.ts). |
| Frontend imports and UI / Imports e interfaz frontend | Use the configured `@/` alias for imports rooted at `src`. Reuse shared UI primitives and the `cn` helper; use the existing CSS variables for theme and chart colors. | Usa el alias configurado `@/` para imports desde `src`. Reutiliza las primitivas UI y el helper `cn`; usa las variables CSS existentes para colores de tema y graficas. | The alias is configured in [vite.config.ts](frontend/vite.config.ts) and [tsconfig.app.json](frontend/tsconfig.app.json); [card.tsx](frontend/src/components/ui/card.tsx) and [utils.ts](frontend/src/lib/utils.ts) show shared UI utilities; tokens are in [index.css](frontend/src/index.css). |
| Testing / Pruebas | Add behavior-focused tests for changed logic. Keep backend tests under `backend/tests/` using `test_*.py`; colocate frontend unit tests with the module they cover using `*.test.ts` or `*.test.tsx`. | Agrega pruebas centradas en comportamiento para la logica modificada. Mantiene las pruebas backend en `backend/tests/` con `test_*.py`; coloca las pruebas unitarias frontend junto al modulo cubierto con `*.test.ts` o `*.test.tsx`. | [test_routes.py](backend/tests/test_routes.py) uses pytest and FastAPI `TestClient`; [financial-utils.test.ts](frontend/src/lib/financial-utils.test.ts) sits beside the utility it tests. |
| Verification evidence / Evidencia de verificacion | Report a check as passed only after executing it. Distinguish static inspection, an existing test, and an executed test result; include the command and outcome when reporting execution. | Informa que una comprobacion paso solo despues de ejecutarla. Distingue inspeccion estatica, test existente y resultado de test ejecutado; al informar ejecucion, incluye comando y resultado. | [verifications.md](verifications.md) records that its review was static and that tests were not run. |
| Synthetic data / Datos sinteticos | Treat generated or fixture data as demo/test data, never as real financial records. Avoid multiple uncoordinated mock sources for the same active flow. | Trata los datos generados o fixtures como datos de demo/prueba, nunca como registros financieros reales. Evita multiples fuentes de mocks descoordinadas para un mismo flujo activo. | The backend generates seeded movements in [routes.py](backend/app/routes.py); [mock-data.ts](frontend/src/lib/mock-data.ts) exists but is not imported by the active app flow in [App.tsx](frontend/src/App.tsx). |
| Local development / Desarrollo local | Use Docker Compose as the documented local entry point. Keep service ports, URLs, and required configuration documented in both README languages. | Usa Docker Compose como punto de entrada documentado para desarrollo local. Documenta en ambos idiomas los puertos, URL y configuracion necesaria. | [docker-compose.yml](docker-compose.yml) defines frontend and backend services; [README.md](README.md) and [README.es.md](README.es.md) document `docker compose up --build`. |
| Configuration and secrets / Configuracion y secretos | Never hardcode secrets, credentials, tokens, API keys, or deployment-specific values in source code or documentation. Read sensitive/environment-specific configuration from environment variables or an approved secret store. Commit safe examples only; never log secrets. | Nunca incluyas secretos, credenciales, tokens, claves API ni valores especificos de despliegue hardcodeados en codigo o documentacion. Lee la configuracion sensible o especifica del entorno desde variables de entorno o un gestor de secretos aprobado. Versiona solo ejemplos seguros; nunca registres secretos en logs. | [.gitignore](.gitignore) excludes `.env` files while allowing `.env.example`; [README.md](README.md) documents `VITE_API_BASE_URL` as environment configuration. |
| Secure deployment defaults / Configuracion segura | Do not deploy development-only settings as production defaults. Restrict CORS to approved origins and disable debug servers, autoreload, and debug ports in production. | No despliegues configuraciones exclusivas de desarrollo como valores predeterminados de produccion. Restringe CORS a origenes aprobados y desactiva servidores de depuracion, autoreload y puertos de debug en produccion. | [main.py](backend/app/main.py) currently allows wildcard CORS; [backend/Dockerfile](backend/Dockerfile) starts Uvicorn with autoreload and debugpy. These are current development settings, not production guidance. |
| Agent guidance / Guia para agentes | `AGENTS.md` is the entry point for agent-specific workflow. Contributors and agents must read it and this standards document before making changes; treat this document as normative project guidance. | `AGENTS.md` es el punto de entrada del flujo especifico para agentes. Colaboradores y agentes deben leerlo junto con este documento antes de realizar cambios; este documento contiene la guia normativa del proyecto. | The existing [AGENTS.md](AGENTS.md) already defines mandatory pre-work guidance and asks agents to inspect project rules. |
| Verification records / Registros de verificacion | Keep verification reports as dated evidence of observed state and checks, not as substitutes for approved standards. Refresh evidence when implementation changes. | Mantiene los informes de verificacion como evidencia fechada del estado observado y de las comprobaciones, no como sustitutos de los estandares aprobados. Actualiza la evidencia cuando cambie la implementacion. | [verifications.md](verifications.md) documents implementation facts, endpoint coverage, and its review limitations. |

## Explicit exclusions / Exclusiones explicitas

The team has not adopted a project-wide automated formatting/lint rule or a backend dependency-pinning rule in this phase. Existing scripts and dependency declarations remain as configured until the team makes a separate decision.

En esta fase el equipo no ha adoptado una regla general de formato/lint automatizado ni una regla para fijar versiones de dependencias backend. Los scripts y declaraciones de dependencias actuales se mantienen como estan hasta que el equipo tome una decision aparte.
